# UBA Luftqualitätsindex (LQI)

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/hacs/integration)
[![GitHub Release](https://img.shields.io/github/release/thorstenhornung1/uba_lqi.svg)](https://github.com/thorstenhornung1/uba_lqi/releases)

Home-Assistant-Integration für die **Luftqualitätsdaten des Umweltbundesamts**
(Air-Data-API **v4**). Sie wählt Messstationen in der Umgebung aus, liefert je
Station den offiziellen **Luftqualitätsindex (LQI)** samt Schadstoff-Messwerten
und bildet zusätzlich einen **kombinierten Index über alle Stationen** eines
Eintrags — den schlechtesten Einzelindex, so wie ihn das UBA definiert.

| Index | Bedeutung |
|---|---|
| 0 | sehr gut |
| 1 | gut |
| 2 | mäßig |
| 3 | schlecht |
| 4 | sehr schlecht |

## Warum ein kombinierter Index?

Nicht jede Station misst alle fünf Indexkomponenten (PM₁₀, PM₂,₅, NO₂, O₃,
SO₂). Ein typisches Beispiel: Die einzige Station in Bonn (Bonn-Auerberg)
misst **kein Ozon** — im Sommer fällt ihre Bewertung dadurch systematisch zu
freundlich aus. Ozon ist jedoch ein flächiger Sekundärschadstoff: Eine
Hintergrund-Station in bis zu ~25 km Entfernung (z. B. Köln-Rodenkirchen) ist
dafür eine fachlich vertretbare Ergänzung. Genau das bildet diese Integration
ab: **PM und NO₂ lokal, Ozon regional, ein gemeinsamer Index.** Je Komponente
zählt dabei die nächstgelegene Station, die sie aktuell liefert.

## Datenqualität als Funktionsmerkmal

- **API v4** — die einzige aktuell gepflegte API-Generation (v2/v3 liefern
  einen Altbestand ohne PM₂,₅ und mit veralteten Index-Schwellen).
- **Zeitstempel korrekt als feste MEZ (UTC+1)** interpretiert — die API kennt
  keine Sommerzeit.
- **Index 0 („sehr gut") ist ein gültiger Wert**, nur -1/fehlend bedeutet
  unbekannt.
- **Veraltete Werte werden nicht als aktuell angezeigt:** Messwerte, die älter
  als 3 Stunden sind, machen die Sensoren `unavailable`. Der Zeitpunkt der
  letzten Messung bleibt als Diagnose-Sensor sichtbar.
- **Hinkende Komponenten gehen nicht verloren:** je Komponente zählt der
  jüngste Wert aus einem 24-h-Fenster.
- **Sichtbares Versagen:** Warnungen im Log, ein Repair Issue, wenn eine
  Station länger als 24 h stumm bleibt, und ein Diagnose-Export.
- **Schonender API-Umgang:** Die Stationsliste (~420 aktive Stationen) wird nur
  bei Einrichtung/Reconfigure geladen, nie zur Laufzeit. Im Fehlerfall steigt
  das Abrufintervall exponentiell (bis 6 h) statt häufiger anzufragen.

## Installation

### HACS (empfohlen)

1. **HACS** öffnen → Menü (⋮) → **Benutzerdefinierte Repositories**
2. `https://github.com/thorstenhornung1/uba_lqi` als Typ **Integration** hinzufügen
3. **UBA Luftqualitätsindex (LQI)** installieren
4. Home Assistant neu starten

### Manuell

1. Ordner `custom_components/uba_lqi` in das `custom_components`-Verzeichnis
   der Home-Assistant-Installation kopieren
2. Home Assistant neu starten

## Einrichtung

**Einstellungen → Geräte & Dienste → Integration hinzufügen → „UBA
Luftqualitätsindex"**

| Schritt | Parameter | Bedeutung |
|---|---|---|
| 1 | Standortquelle | Home-Assistant-Standort oder Karte |
| 1 | Suchradius (5–200 km, Standard 50) | Nur Stationen in diesem Umkreis werden angeboten |
| 2 | Standort (nur bei „Karte") | Koordinaten per Kartenauswahl |
| 3 | Messstationen | Mehrfachauswahl, nach Entfernung sortiert, mit Stationstyp/-umgebung |

Empfehlung: die nächstgelegene **Hintergrund**-Station wählen; misst sie kein
Ozon, eine zweite Station mit Ozon ergänzen. Verkehrsnahe Stationen bewerten
die eigene Wohnlage meist zu schlecht.

Eine Station kann nur zu **einem** Eintrag gehören. Mehrere Einträge (z. B.
Zuhause und Arbeitsplatz) sind möglich.

### Optionen

**Eintrag → Konfigurieren:** Abrufintervall 15–360 min (Standard 60). Das UBA
veröffentlicht stündlich neue Werte, typischerweise ~50 Minuten nach der
vollen Stunde — häufigeres Abfragen bringt keine neueren Daten.

**Eintrag → ⋮ → Neu konfigurieren:** Standort, Radius und Stationsauswahl
ändern, ohne den Eintrag zu löschen.

## Entitäten

Je Station entsteht ein Gerät, dazu ein Service-Gerät **„Luftqualität
kombiniert"**:

| Entität | Gerät | Standard | Beschreibung |
|---|---|---|---|
| Luftqualitätsindex | Station | aktiv | LQI der Station (schlechtester Einzelindex), Zustände „sehr gut" … „sehr schlecht" |
| Schadstoff-Sensoren (PM₁₀, PM₂,₅, NO₂, O₃, SO₂, CO, …) | Station | aktiv¹ | Konzentration mit Geräteklasse und Einheit der API; Index und Messzeit als Attribute |
| Letzte Messung | Station | aktiv (Diagnose) | Ende des jüngsten Messintervalls — zeigt Datenstau sofort |
| Entfernung | Station | deaktiviert (Diagnose) | Distanz zum konfigurierten Standort |
| Luftqualitätsindex (numerisch) | Station | deaktiviert (Diagnose) | 0–4 für Automationen |
| Luftqualitätsindex | kombiniert | aktiv | Schlechtester Einzelindex, je Komponente von der nächstgelegenen Station, die sie liefert; Attribute zeigen je Komponente Wert, Quelle und Treiber |
| Luftqualitätsindex (numerisch) | kombiniert | deaktiviert (Diagnose) | 0–4 |

¹ Exotische Komponenten (Blei, Benzo(a)pyren, …) sind standardmäßig deaktiviert.

Welche Schadstoff-Sensoren angelegt werden, bestimmen die bei der Einrichtung
über ein 48-h-Fenster ermittelten und gespeicherten Stationsmetadaten — nicht
die erste API-Antwort. Nach einem Neustart fehlen daher keine Entitäten, auch
wenn eine Komponente gerade aussetzt.

## Beispiele

Ozon-Warnung über den kombinierten Index:

```yaml
automation:
  - alias: "Warnung bei schlechter Luft"
    triggers:
      - trigger: state
        entity_id: sensor.luftqualitat_kombiniert_luftqualitatsindex
        to:
          - poor
          - very_poor
    actions:
      - action: notify.mobile_app
        data:
          message: >
            Luftqualität {{ states('sensor.luftqualitat_kombiniert_luftqualitatsindex') }} —
            Treiber: {{ state_attr('sensor.luftqualitat_kombiniert_luftqualitatsindex', 'worst_component') }}
```

Numerischer Vergleich (Diagnose-Sensor aktivieren oder Attribut nutzen):

```yaml
{{ state_attr('sensor.luftqualitat_kombiniert_luftqualitatsindex', 'lqi') >= 2 }}
```

## Bekannte Einschränkungen

- Die API liefert Stundenmittel mit ~1 h Verzug; „Echtzeit" gibt es nicht.
- SO₂ und CO messen nur wenige Stationen; der Index funktioniert trotzdem
  (schlechtester **vorhandener** Einzelindex).
- Keine Vorhersage — nur Messwerte.
- Beim Umstieg von Version 1.x werden Einträge automatisch migriert, die
  Entitäten sind jedoch neu (Breaking Change, siehe CHANGELOG); Automationen
  müssen angepasst werden.

## Fehlerbehebung

- **Sensoren `unavailable`:** Sensor „Letzte Messung" prüfen. Liegt sie
  Stunden zurück, liefert die Station nicht — nach > 24 h erscheint ein
  Repair Issue mit Hinweis. Bleibt die Station stumm, per **Neu
  konfigurieren** ersetzen.
- **Log:** Die Integration warnt einmalig, wenn eine Station keine frischen
  Daten mehr liefert, und meldet die Erholung.
- **Diagnose:** Eintrag → ⋮ → **Diagnose herunterladen** (Heimkoordinaten
  werden geschwärzt).
- Debug-Log:

```yaml
logger:
  logs:
    custom_components.uba_lqi: debug
```

## Entfernen

Eintrag unter **Einstellungen → Geräte & Dienste** löschen — Geräte,
Entitäten und Repair Issues werden mit entfernt. Bei manueller Installation
anschließend den Ordner `custom_components/uba_lqi` löschen. Die Integration
hinterlässt keine weiteren Daten.
